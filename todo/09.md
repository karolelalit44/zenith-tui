# 09 — Outstanding Issues Resolution & Generic Architecture Hardening

## 1. Objective

Resolve every outstanding issue recorded at the end of task 08, and harden the
architecture so each fix is generic, config-driven, and not tied to one
file/model/provider/scenario — consistent with a top-grade agentic product
(Cursor / Claude Code / Codex class).

## 2. Scope / Rules

1. Solutions must be generic and extensible, never hardcoded, bounded, or
   narrow. Prefer configuration/abstraction over special-casing.
2. **Interactive question tool is REMOVED** (user decision: not needed now).
   Remove the tool, its capability/registration, its tests, and all references —
   no half-removals, no fake "unavailable" paths left behind.
3. Fix the 13 pre-existing `ruff format --check` failures so the backend is
   fully format-clean.
4. Remove TUI import-time env fragility: runtime config centralized in the
   existing config module (`tui/src/config/appConfig.ts`) with documented
   defaults — consistent with the rest of the app.
5. Remove remaining dead API surface only when confirmed dead on both ends
   (client + backend). Keep genuine API for real features.
6. Improve the summarizer async boundary pattern to a clean, standard form
   (no `asyncio.run` inside `to_thread`) if the call-site allows.
7. Clean workspace artifacts (`.audit_tmp`).
8. `todo/09.md` documents objective, scope, changes, files, validation,
   remaining issues. Mark sections complete only after verification.
9. No git commits unless explicitly asked (GUIDELINES §2).
10. Validation order: `ruff check` → `ruff format --check` → `pytest` →
    `npm run lint` → `npm test` → `tsc --noEmit` → `build`.

## 4. Changes made

1. **Removed the interactive `question` tool entirely** (user decision):
   - Deleted `server/toolkit/tools/question.py`.
   - Unregistered it in `server/toolkit/__init__.py` (import, `__all__`,
     `registry.register(...)`).
   - Removed the `interactive_question` capability descriptor from
     `server/toolkit/catalog.py`.
   - Removed `PERMISSION_INTERACTION` from `server/config/constants.py` and from
     `_VALID_PERMISSION_SCOPES` in `server/toolkit/registry_validation.py`
     (the only remaining consumer after tool removal).
   - Updated tests: `server/tests/test_tools.py` and
     `server/tests/test_tool_catalog.py` (tool count 20 -> 19, capability list).
   - Cleaned the stale "excluded: question" notes in
     `scripts/smoke_tool_exercise.py`.
   - Verified zero remaining references repo-wide (`QuestionTool`,
     `interactive_question`, `PERMISSION_INTERACTION`, `tools.question`).

2. **Fixed all 16 `ruff format` failures** so the whole repo is format-clean:
   13 server files (`server/agents/loop.py`, `server/config/constants.py`,
   `server/tests/{test_compaction,test_error_messages,test_integration,
   test_loop_regression,test_rate_limiting,test_tools}.py`,
   `server/toolkit/tools/{_html_text,bash,glob,webfetch,websearch}.py`) plus 3
   smoke scripts (`smoke_confirm_flow.py`, `smoke_tool_exercise.py`,
   `smoke_tui_session.py`). Also fixed a pre-existing `E741` ambiguous-variable
   (`l`) in `scripts/smoke_tui_session.py`.

3. **Centralized TUI git runtime config** in the existing config module:
   - `tui/src/config/appConfig.ts` gains `git.cacheTtlMs` (env
     `ZENITH_GIT_CACHE_TTL`, default 30000) and `git.timeoutMs` (env
     `ZENITH_GIT_TIMEOUT` in seconds x 1000, default 30 s).
   - `tui/src/services/git.ts` reads from `appConfig` instead of calling
     `requireInt(...)` at module import, so a missing env var can no longer
     crash the TUI. This also fixed a latent bug: the timeout was previously
     passed to `execSync` in milliseconds (30 ms), so the git branch lookup
     would effectively always time out; it now honors the documented seconds
     semantics (30 s).

4. **Cleaned the summarizer async boundary**
   (`server/agents/summarizer.py`): replaced `asyncio.to_thread(asyncio.run(
   coro))` under `wait_for` with a direct `await asyncio.wait_for(...)`. Both
   call sites (`server/agents/loop.py`, `server/api/handlers.py`) are async and
   every `BaseProvider.complete` is a non-blocking coroutine (e.g.
   `LLMProvider` awaits `litellm.acompletion`), so the thread hop was
   unnecessary.

5. **Workspace artifact `.audit_tmp/`**: added to `.gitignore`. Physical
   deletion is OS-blocked: the directory carries restrictive ACLs
   (`Get-Acl` and `Remove-Item` fail with `UnauthorizedAccessException`); it is
   empty and git no longer scans it.
