# 08 — Deep Codebase Cleanup, Configuration Hardening & Sanity Checks

## 1. Objective

Deep cleanup and hardening of the entire codebase:

* Remove unnecessary hardcoded/static values, excessive comments, file/model-specific configuration, fallback behavior, obsolete code, and other technical debt.
* Final codebase must be clean, maintainable, generic, configuration-driven, database-driven where appropriate, environment-driven only for runtime/startup configuration, free from unnecessary fallback behavior and obsolete code, consistent across frontend and backend, and suitable for a broader AI/agentic system.

**Do not make superficial changes. Inspect the entire codebase and understand how each value, configuration, function, and fallback is actually being used before removing or changing it.**

## 2. Scope / Cleanup rules

1. **Static values** — for each, choose: derived dynamically (preferred), reusable constant, database, or environment variable. `.env` holds ONLY runtime/startup configuration; do NOT move every hardcoded value into `.env`.
2. **Constants** — centralize genuinely-static values in a dedicated constants module (e.g. `server/config/constants.py`); avoid scattering duplicates and avoid meaningless constants.
3. **Comments** — remove long/obvious/stale/debug/commented-out/TODO-style comments; keep only genuinely necessary context. Prefer self-explanatory code.
4. **File/model/scenario-specific config** — generalize or remove `if model == X`, `TASK_X_PROMPT`, `SPECIAL_CONFIG_FOR_MODEL_X` patterns; use generic interfaces, provider abstractions, capabilities, metadata, DB config, reusable services.
5. **Fallbacks** — remove silent fallback values that hide failures (default/secondary/cached/placeholder/other-model/provider). Primary op fails → raise/propagate → emit/broadcast → consumer handles.
6. **Exception propagation** — raise appropriate exceptions, preserve failure reason, propagate through layers, broadcast where the architecture expects it, let consumers handle/display. No `except: return default`.
7. **Obsolete code** — audit files/folders/functions/classes/imports/dead code/duplicates/unused constants/legacy utils; verify references before deleting; remove only what is confirmed obsolete.
8. **Second sweep** — re-search backend + frontend for hardcoded numbers/strings/URLs/model ids/provider ids/limits/timeouts/paths/env assumptions/feature flags/static lists/duplicated values.
9. **Do not over-engineer** — pick the simplest correct solution per value (why does it exist, who owns it, runtime config vs app config vs persistent data vs derivable vs constant vs obsolete).
10. **Tracking** — `todo/08.md` documents objective, scope, rules, areas inspected, changes, files affected, obsolete code removed, fallbacks removed, constants introduced, config changes, architectural changes, validation, remaining issues. Mark sections complete only after verification.

## 4. Changes made

### Backend — failure-hiding fallbacks removed / exceptions propagated
- `server/toolkit/middleware/permission.py` — `before_execute` previously failed **open** (`except Exception: return True`). Now logs `logger.warning` and returns a `ToolResult(success=False, ...)` deny on any service/callback error. Added missing `logger`.
- `server/permissions/service.py` — base `PermissionService` stubs (`...`/`pass`) silently returned `None`; now raise `NotImplementedError`. Fixed latent `AttributeError`: `DefaultPermissionService.__init__` never initialized `_callback`, referenced in `request()`.
- `server/workspace/git.py` — removed import-time `require_int("ZENITH_GIT_TIMEOUT")` (crashed at import when unset; env is documented and optional in `settings`). Now resolved lazily in `_run` via `_git_timeout()` (`optional_int` default 30, aligned with `ToolConfig.max_bash_timeout` pattern and `.env.example`). `_run` no longer swallows unexpected exceptions into `(-1, "", str(e))`; only `FileNotFoundError` and `TimeoutExpired` remain graceful returns (unexpected errors now propagate + are surfaced).
- `server/toolkit/tools/question.py` — when no interactive handler is registered (`_question_callback is None`, currently always the case — no setter exists), the tool returned `success=True` with a fake "question asked" output. Now returns `success=False` with `interaction_unavailable` error + metadata.
- `server/agents/provider_adapters.py` — catalog load failure logged at `debug` (invisible) → `warning`. FLAGSHIP defaults for unknown/absent models and malformed `prompt_tier` remain (documented semantic defaults, not failure-hiding).

### Backend — dead code / constants / config

- `server/agents/validation.py` — removed dead `REFLECTION_ERROR_LIMIT = 6`.

- `server/agents/summarizer.py` — **kept as-is**: the heuristic `_fallback` on timeout/failure is intentional graceful degradation for compaction (logged at `warning`), not a silent failure-hide.

## 7. Fallbacks removed

- Permission middleware: `except Exception: return True` → deny on error (log + `ToolResult(success=False)`).
- `PermissionService` base class stubs: implicit `None` → `NotImplementedError`.
- `question` tool: fake `success=True` when no handler → `success=False` + explicit `interaction_unavailable`.
- `git._run`: unexpected exception swallowed → propagates (only `FileNotFoundError`/`TimeoutExpired` stay graceful).
- `provider_adapters`: catalog-load failure `debug` → `warning`.
- Kept intentionally: summarizer heuristic fallback (graceful degradation for compaction); `FLAGSHIP`/catalog defaults for unknown models (semantic defaults); TUI `.env` module defaults (documented runtime config); `ProviderRepository` fallback usage (established consumer pattern); `ValidationProgress` runId (real retry).
